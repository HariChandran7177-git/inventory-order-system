# API Reference

Both services expose OpenAPI documentation at `/docs` while running. Base paths are relative to their respective origins: Inventory defaults to `http://localhost:8000`; Payment defaults to `http://localhost:8001`.

## Inventory service

| Method | Path | Input | Result |
|---|---|---|---|
| GET | `/health` | — | `{"status":"ok","service":"inventory"}`; process-only health. |
| GET | `/inventory/products` | — | Array of products (`id`, `name`, `price`, `quantity`, `creation_time`). |
| GET | `/inventory/product/{pk}` | Product key | Product object; missing product is reported by the service's not-found exception handler. |
| POST | `/inventory/product` | `{ "name": "Desk lamp", "price": 24.5, "quantity": 12 }` | Created Redis product. |
| PUT | `/inventory/product/{pk}` | Any supplied subset of `name`, `price`, `quantity` | Updated product. |
| DELETE | `/inventory/product/{pk}` | Product key | Deleted product data. |

Product names must contain 1–120 characters, and price and quantity must be non-negative. Invalid create/update values return FastAPI validation errors (422). The routes still have no authentication or authorization.

## Payment service

| Method | Path | Input | Result |
|---|---|---|---|
| GET | `/health` | — | `{"status":"ok","service":"payment"}`; process-only health. |
| POST | `/orders/` | `{ "product_id": "<inventory id>", "order_quantity": 2 }` | New order with calculated unit price, fee, total and initially `pending` status. Quantity must be greater than zero. |
| GET | `/orders/` | — | Array of order records. |
| GET | `/orders/{order_id}` | Integer order ID | One order or 404. |
| PUT | `/orders/{order_id}` | Any supplied subset of order fields | Updated order or 404. |
| DELETE | `/orders/{order_id}` | Integer order ID | Deleted order data or 404. |

Order creation calls Inventory synchronously. Inventory connection failures and unexpected responses produce gateway errors; unknown product produces 404; requested quantity greater than current stock produces 400. The payment API then persists the order and schedules background processing. The worker/event outcome can update state asynchronously.

## Security and limits

No endpoint currently enforces authentication, authorization, pagination, or rate limits. Do not expose the APIs to untrusted networks in their current state. Error details and status codes are generated by FastAPI and service logic; clients should not assume every error body has the same shape beyond FastAPI's usual `detail` field.
